# ARC-GPT2 Design

## 1. Research claim

ARC-GPT2 does not claim that raw GPT-2 can solve ARC-AGI-3. It tests whether the pretrained GPT-2 causal transformer can be converted into a compact **learning algorithm** rather than a static policy.

The target behavior is:

1. observe an unfamiliar game;
2. spend early actions identifying action semantics and transition rules;
3. preserve contradictions and terminal failures;
4. infer a provisional goal from successful and failed attempts;
5. improve within the same game and across its levels;
6. act efficiently without another learned model or an external planner.

The key method is **Counterfactual Fracture Distillation (CFD)**:

- During offline data generation, exact Bayes-adaptive/CFS-style learners, generic search, and human replays generate full *learning histories*, not merely final expert paths.
- GPT-2 is trained as a causal sequence model to predict the next internal record and action from those histories.
- During evaluation, the source algorithms are removed. Only GPT-2 and a deterministic interface remain.

This is algorithm distillation specialized for hidden-rule interactive grid worlds.

## 2. Strict purity contract

### Allowed at inference

- one checkpoint from the original GPT-2 family;
- one tokenizer/vocabulary associated with that checkpoint, extended with ARC grammar tokens;
- repeated calls to the same checkpoint under different mode tokens;
- deterministic, lossless serialization of frames and frame deltas;
- a bounded transcript and GPT-2-generated recurrent memory;
- legal-action filtering and syntactic validation;
- deterministic sampling/argmax and fixed self-consistency voting over outputs from the same checkpoint;
- optional online gradient updates to that same GPT-2 checkpoint or its attached low-rank parameters, provided no other model supplies targets.

### Forbidden at inference

- any second learned model;
- a separate visual encoder, object detector, affordance model, value model, reward model, critic, reranker, or embedding model;
- external LLM calls;
- game-specific branches or hard-coded solution rules;
- BFS, A*, MCTS, program synthesis, symbolic world-model execution, or handcrafted goal inference used to select the action;
- reading environment source code or private mechanics;
- retrieval of public-game solutions.

### Deterministic interface rule

The interface may answer only these mechanical questions:

- How is the exact grid serialized?
- Which actions are currently legal?
- Is the model output syntactically valid?
- What action token and optional coordinates did the model emit?
- Which transcript tokens fit inside the context budget?

It may not answer semantic questions such as which cells form an object, which action is promising, whether progress occurred, or what the goal is. Those must be learned and generated by GPT-2.

## 3. Why the prior ARC line plateaued

The previous public work produced three grounded findings:

- visually consequential actions can be ranked above chance;
- visible change is not equivalent to task value;
- remembered terminal failure can improve a counterfactual retry.

But the repaired policy solved only two development-involved public games and none of the other 23. The main defect was not insufficient search depth. It was the absence of a transferable mechanism that jointly represented:

- action semantics;
- transition dynamics;
- goal evidence;
- cross-attempt memory;
- cross-level reuse.

A larger handcrafted controller would likely accumulate more local heuristics without solving that transfer problem. ARC-GPT2 therefore moves the learning algorithm into a single sequence model and measures whether it can acquire these variables from interaction history.

## 4. GPT-2 as a recurrent interactive machine

GPT-2 is used as a repeated transition operator over a textual/symbolic tape.

At environment time `t`, the tape is:

```text
<GAME>
<MEMORY> bounded persistent game belief </MEMORY>
<RECENT>
  prior frame/action/outcome records
</RECENT>
<CURRENT_FRAME> exact compressed grid </CURRENT_FRAME>
<AVAILABLE> legal action tokens </AVAILABLE>
<BUDGET> remaining action/reset budget </BUDGET>
<MODE> ... </MODE>
```

The same model is called in five modes.

### 4.1 NARRATE

Input: previous frame, current frame, action, status.

Output: a concise event record such as:

```text
<EVENT> cyan region translated x+1; red region unchanged; no terminal </EVENT>
```

The narration is not trusted as ground truth. It is an internal representation trained from synthetic exact labels and human trajectories. The exact frame remains available in recent context.

### 4.2 BELIEF

Input: old memory plus recent exact events.

Output: a replacement fixed-length memory:

```text
<MEMORY>
A1 likely dx=-1 confidence 3/3;
A4 likely dy=+1 confidence 2/2;
contact red preceded GAME_OVER;
yellow removal persisted after reset? unknown;
goal candidates: collect-yellow 0.55, reach-green 0.30;
failed prefix hash=...;
</MEMORY>
```

Only the latest memory is carried indefinitely. This gives GPT-2 recurrence beyond its native context window.

### 4.3 IMAGINE

Input: memory, current frame, one candidate legal action.

Output:

```text
<PREDICT>
<DELTA> ... </DELTA>
<STATUS> NOT_FINISHED </STATUS>
<UTILITY> +2 </UTILITY>
<UNCERTAINTY> 3 </UNCERTAINTY>
</PREDICT>
```

All candidate predictions are produced by the same GPT-2. No external world model exists.

### 4.4 ACT

Input: memory, frame, legal actions, and optionally GPT-2's own imagined outcomes.

Output:

```text
<ACTION> A3 </ACTION>
```

or:

```text
<ACTION> A6 X17 Y09 </ACTION>
```

### 4.5 REFLECT

Called after WIN, GAME_OVER, RESET, or level transition. It compresses the attempt into persistent memory and explicitly distinguishes:

- confirmed dynamics;
- contradicted dynamics;
- tentative goal evidence;
- terminal prefixes;
- reusable facts versus level-specific geometry.

## 5. Recursive deliberation with one model

A 124M model has limited single-pass depth. We trade time for depth by looping the same model.

A decision may use:

1. one BELIEF pass;
2. four to twelve IMAGINE passes, one per action/candidate coordinate;
3. two independent ACT samples;
4. one REFLECT/CRITIQUE pass if the samples disagree;
5. deterministic voting over valid action outputs.

This is not an ensemble: every pass shares identical weights. It is a looped GPT-2 computation whose intermediate tokens are visible and trainable.

A later variant will use `PONDER_1...PONDER_k` tokens and train the model to refine its own proposal across a variable number of recurrent passes. Improvement with additional passes will be measured explicitly; extra tokens are not assumed to equal reasoning.

## 6. Exact frame codec

The first observation may contain up to 4,096 cells, while GPT-2 has a 1,024-token native context. The codec must therefore be compact, exact, and free of semantic assumptions.

For each frame the interface constructs three lossless encodings and selects the shortest:

### 6.1 Row run-length encoding

```text
<GRID H08 W08>
<R> C0 N5 C3 N2 C0 N1
...
</GRID>
```

All colors, dimensions, and run lengths are single special tokens.

### 6.2 Quadtree/rectangular split encoding

Uniform regions are color leaves. Non-uniform regions are split deterministically along the longer axis. This compresses large backgrounds and rectangular structure without identifying objects.

```text
<Q H64 W64> SX32 C0 SY16 C4 ... </Q>
```

### 6.3 Sparse delta encoding

After the initial frame, only changed cells/rectangles are transmitted when this is shorter than a full frame.

```text
<DELTA>
<X12 Y08 OLD0 NEW3>
<RECT X13 Y08 W03 H02 OLD0 NEW3>
</DELTA>
```

The current frame can always be reconstructed exactly from the initial frame and deltas. Periodic full-frame checkpoints prevent error accumulation in long transcripts.

### 6.4 Context budgeting

The target budget is:

- recurrent memory: 96–160 tokens;
- current frame: at most 512 tokens in the common case;
- recent exact transitions: 200–300 tokens;
- mode/output allowance: 100–200 tokens.

If a frame still exceeds budget, it is divided into deterministic spatial chunks. The same GPT-2 narrates each chunk, then receives the chunk narrations plus a low-resolution exact overview. No learned encoder is introduced.

## 7. ARC vocabulary

The tokenizer is extended with atomic tokens for:

- tags and modes;
- `C0..C15` colors;
- `X0..X63`, `Y0..Y63` coordinates;
- `N0..N64`, `H0..H64`, `W0..W64` counts/dimensions;
- `A1..A7`, `RESET`;
- `NOT_FINISHED`, `WIN`, `GAME_OVER`;
- codec operators;
- utility/confidence buckets;
- bounded memory punctuation.

The existing GPT-2 vocabulary remains available for natural-language concepts and compositional rule descriptions. New embeddings are trained; old embeddings are not discarded.

## 8. Training objective

There is still one causal language-model head. Different target spans receive different weights:

| Target span | Weight |
|---|---:|
| chosen action and coordinates | 10 |
| terminal/status prediction | 6 |
| next-frame delta | 4 |
| utility/progress bucket | 4 |
| recurrent memory | 2 |
| narration/rule text | 1 |

Input/history tokens are masked from loss. The model is not rewarded for copying the prompt.

The principal training forms are:

### 8.1 Action conditional modeling

Predict the teacher/source learner's next action from the entire learning history.

### 8.2 Forward dynamics

Predict the exact sparse delta and terminal state after a chosen action.

### 8.3 Inverse dynamics

Given two frames, predict the action that caused the transition. This anchors new grid tokens to action semantics.

### 8.4 Return-conditioned behavior

Sequences contain desired return/efficiency buckets. At inference the model is conditioned on the highest attainable return. Failed trajectories remain in the dataset so the model learns the difference between exploration that eventually pays off and visually dramatic failure.

### 8.5 Algorithm distillation

The training corpus contains whole learning histories across attempts and levels. The target action is generated by a source learner at that point in its own learning process, not by an omniscient expert alone. This teaches improvement from context.

### 8.6 Memory distillation

Synthetic generators expose exact hidden mechanics and goals during training. These are rendered into a canonical bounded belief record, giving direct supervision for memory. Later training corrupts and partially removes the canonical memory so GPT-2 must repair its own generated summaries.

## 9. Data curriculum

### Phase 0 — hidden action meta-learning

Random permutation of `A1..A4` to movement directions, fixed across several levels of one game. Randomized colors, geometry, starts, goals, obstacles, and level order.

Purpose: prove that GPT-2 learns from action-outcome history rather than a static frame policy.

### Phase 1 — primitive dynamics

Procedural families:

- collision and boundaries;
- push/pull;
- collect/remove;
- toggle/open/close;
- pick/drop/attach/detach;
- rotate/reflect;
- teleport;
- paint/copy;
- click/select with coordinates;
- projectile and delayed transitions;
- reversible versus irreversible actions.

Every family is parameterized and palette/action remapped.

### Phase 2 — hidden goals

Goals are not stated. Families include:

- reach;
- collect all;
- avoid;
- match a target pattern;
- order a sequence;
- transform one configuration into another;
- assemble/disassemble shapes;
- activate dependencies;
- synchronize moving entities;
- discover a latent terminal predicate.

Training histories include failed interpretations followed by corrected behavior.

### Phase 3 — fracture curriculum

Use the exact CFS/Bayes-adaptive planner on small generated partially observed worlds to produce histories where the useful action has no immediate information gain but leads to a later discriminating experiment.

GPT-2 must learn this exploration pattern from sequence prediction. At test, no CFS code is called.

### Phase 4 — cross-level games

A hidden game genome remains stable while layouts become harder across levels. The recurrent memory must separate reusable mechanics from local geometry.

### Phase 5 — human ARC-AGI-3 replays

Use the released step-by-step human replays from public games. Train on complete attempts, including inefficient exploration and recoveries, with score/efficiency conditioning.

No public game used for evaluation may contribute its replay or environment trajectory to training in that fold.

### Phase 6 — public environment self-play

Run the current GPT-2 on public environments, record failures and successes, and continue training on actual transition prediction. Retain locked game-level splits. Never promote a result obtained on a development-involved game as transfer evidence.

## 10. Test-time learning variants

The baseline relies entirely on in-context adaptation.

Only after that baseline is measured will two online variants be considered:

### 10.1 Transition-only LoRA update

A temporary per-game adapter is updated from observed `(history, action -> actual delta)` targets. Base weights remain frozen. The update never uses hidden reward labels or another model.

### 10.2 Meta-learned fast update

Train the base model so a few transition-loss gradient steps improve later action selection on held-out synthetic games. This is more expensive and will be attempted only if ordinary online updates improve dynamics but damage the policy.

Online learning is accepted only if it improves held-out game completion and not merely next-frame loss.

## 11. Evaluation ladder

### 11.1 Phase-0 decisive controls

- intact history;
- current-frame-only amnesia;
- shuffled action/outcome history;
- incorrect-memory injection;
- pretrained GPT-2 initialization;
- random GPT-2 initialization with identical architecture;
- frozen base with only new embeddings trained;
- full/partial fine-tuning.

Passing requires a substantial intact-history advantage and better efficiency on later levels.

### 11.2 Synthetic family holdouts

Hold out whole mechanic/goal compositions, not merely random seeds. Measure:

- game and level completion;
- actions relative to oracle;
- first-attempt versus later-attempt improvement;
- action-semantic identification;
- exact next-delta accuracy;
- calibration of terminal and utility predictions;
- memory faithfulness under perturbation.

### 11.3 ARC public locked folds

Use leave-one-game-out or larger family-level locked folds. For each target game:

- no trajectories, human replays, code-derived labels, or mutations of that game in training;
- one predeclared run configuration;
- exact checksums and model artifact;
- action budget matched to baseline;
- no post-hoc game-specific edits.

The prior frozen benchmark remains the comparison point: FT09 6/6, LS20 2/7, 8/183 levels overall in the staged system, and the separate repaired general policy with 2/25 development-involved games but no transfer to the other 23.

### 11.4 Official Kaggle submission

A submission is justified only after a locked public fold improves by at least one genuinely held-out game or produces a clear action-efficiency gain across several games.

The Kaggle notebook will contain the checkpoint, tokenizer, deterministic codec, GPT-2 loop, and no network dependency.

## 12. Scaling decisions

### GPT-2 Small — 124M

Primary scientific model. Full fine-tuning is feasible. Used for architecture, curriculum, ablation, and interpretability.

### GPT-2 Medium — 355M

Promoted only if Small passes the in-context learning gate and shows positive locked synthetic transfer. Use full or selective fine-tuning depending on memory.

### GPT-2 Large/XL — 774M/1.5B

Used only after Medium produces held-out ARC improvement. Parameter-efficient adaptation and gradient checkpointing are expected. A larger checkpoint is not a substitute for a failed learning algorithm.

## 13. Kaggle GPU plan

A Kaggle GPU is used for training and official inference, not for environment simulation.

Initial jobs:

1. train Phase-0 GPT-2 Small under six controls;
2. run 1,000+ held-out synthetic games;
3. archive model, data manifest, metrics, and raw trajectories;
4. only then train primitive/goal curricula.

The training notebook must be launchable by the Kaggle CLI once an account token is stored outside the model code. Until that connection exists, CPU GitHub Actions can run smoke-scale proofs and produce artifacts.

## 14. Failure conditions

The GPT-2-only hypothesis is considered unsupported if any of these remain true after representation and curriculum debugging:

- intact history does not beat amnesia;
- pretrained GPT-2 does not beat the random-initialized architecture;
- gains disappear under unseen action/color permutations;
- transition prediction improves but completion does not;
- recurrent memory is ignored or corrupted;
- recursive deliberation adds tokens but not performance;
- public-game gains occur only on development-involved environments;
- the model requires an external planner to turn its predictions into useful action.

A negative result would still be informative: it would separate the value of GPT-2 pretraining from the generic value of causal transformers for meta-RL.

## 15. Immediate implementation order

1. Freeze this purity contract and evaluation gates.
2. Implement and test the lossless codec.
3. Implement the hidden-action multi-level generator.
4. Build deterministic source learning histories.
5. Fine-tune GPT-2 Small on action-only prediction.
6. Run intact/amnesic/shuffled controls.
7. Add recurrent memory only after raw context learning is demonstrated.
8. Add forward-dynamics and fracture-distillation objectives.
9. Integrate public human replays under game-level locks.
10. Package the first honest ARC-GPT2 agent for local public evaluation.

No scale-up is approved by default. Evidence at each gate determines the next run.
