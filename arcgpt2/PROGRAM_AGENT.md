# ARC-GPT2 Program Agent

## Decision after deeper review

The earlier purity contract was too restrictive. It prohibited generic search,
program synthesis, and executable verification even though those are ordinary
computation rather than competing learned intelligence. That would force a
124M–1.5B parameter model to perform exact simulation and long-horizon planning
inside one forward pass, which is the least favorable use of GPT-2.

The stronger interpretation of **just GPT-2** is now:

> GPT-2 is the only learned model and the only source of semantic hypotheses,
> action proposals, memories, programs, and value judgments. Deterministic code
> may losslessly expose observations, enforce syntax, execute GPT-2's programs,
> replay evidence, calculate probabilities, and search consequences predicted
> by those programs.

No other neural network, LLM, vision encoder, embedding service, classifier,
critic, reranker, or hand-written game policy is permitted.

This changes ARC-GPT2 from a direct policy into an **executable Bayesian program
learner**.

## Core thesis

ARC-AGI-3 is not primarily an action-prediction problem. It is a latent-program
identification problem:

- an unknown transition program determines action effects;
- an unknown goal program determines which states matter;
- observations eliminate candidate programs;
- efficient play requires experiments that distinguish programs;
- once a compact program is known, ordinary computation can execute and plan
  with exactness far beyond GPT-2's internal arithmetic reliability.

GPT-2's job is therefore not simply to emit the next action. Its central job is
to propose, repair, rank, and use compact executable explanations.

## One model, six roles

Every role below is performed by the same GPT-2 checkpoint and LM head. Mode
tokens alter the requested output but do not select another network.

1. `INSPECT` — request an exact crop, diff, row, column, or full-grid view.
2. `INDUCE` — generate candidate mechanics and goal programs in ARC-DSL.
3. `REPAIR` — revise a candidate program after an exact replay contradiction.
4. `IMAGINE` — predict an outcome directly when no program is yet adequate.
5. `PLAN` — generate candidate action sequences or macro-actions under a live
   program posterior.
6. `ACT` — choose the real environment action after seeing verified rollouts,
   uncertainty, budget, and prior failures.

Repeated calls are permitted. They are recurrent computation with tied GPT-2
weights, not an ensemble of different models.

## Deterministic tool surface

The harness is deliberately narrow and inspectable.

### Observation tools

- `FULL()` — exact losslessly compressed grid;
- `CROP(x, y, w, h)` — exact rectangular cells;
- `DIFF(t0, t1)` — exact changed coordinates and old/new values;
- `ROW(y)` / `COL(x)` — exact one-dimensional views;
- `HISTORY(n)` — exact last `n` environment records;
- `REPLAY(attempt_id)` — exact earlier attempt.

These tools perform no salience detection, object recognition, or goal
inference. GPT-2 decides what to inspect and what it means.

### Program tools

- `COMPILE(program)` — grammar/type validation;
- `CHECK(program, history)` — exact replay against all recorded transitions;
- `RUN(program, state, action)` — one predicted transition;
- `ROLLOUT(program, state, actions)` — predicted trajectory;
- `SEARCH(program_set, state, budget)` — generic graph/beam search over states
  generated by candidate programs;
- `DISAGREE(program_set, state, action)` — partition candidates by predicted
  result;
- `MINIMIZE(program, history)` — semantics-preserving simplification under the
  recorded evidence.

The tools do not invent programs or select their semantics. They execute what
GPT-2 generated.

## ARC-DSL

Python is too broad and brittle for GPT-2. ARC-DSL is a typed, bounded language
whose programs are short enough for GPT-2 Small and exact enough for replay.

### Data types

- `Cell`, `Color`, `Coord`, `Region`, `Shape`, `Frame`;
- `Entity`, `Set[Entity]`, `Bool`, bounded `Int`;
- persistent `Var` values for inventory, toggles, counters, selections, and
  hidden phase.

### Perception expressions

The interpreter provides generic mathematical operations, not learned labels:

```text
COLOR(c)
CELLS(predicate)
COMPONENTS(c, connectivity)
BBOX(region)
SHAPE(region)
COUNT(set)
AT(x, y)
NEAREST(source, target)
RAY(origin, direction)
MATCH(shape_a, shape_b, transforms)
```

### Transition statements

```text
ON A1: MOVE(selector, dx=-1, dy=0, collision=BLOCK)
ON A6(x,y): TOGGLE(ENTITY_AT(x,y))
ON CONTACT(player, key): REMOVE(key); SET(inventory,key,1)
ON CONTACT(player, door) IF GET(inventory,key): OPEN(door)
AFTER n STEPS: TRANSLATE(selector, dx, dy)
```

### Goal predicates

```text
GOAL: AT(player, target)
GOAL: COUNT(COLOR(yellow)) == 0
GOAL: SHAPE(assembly) == SHAPE(template)
GOAL: ALL(buttons, state == ON)
GOAL: FRAME == target_frame UNDER palette_permutation
```

### Program discipline

- bounded loops only;
- no filesystem, network, reflection, or arbitrary Python;
- deterministic execution;
- every primitive has canonical serialization;
- programs are hashable and can be compared by behavior over recorded states;
- grammar-constrained decoding prevents syntactically invalid token sequences.

## Posterior over executable hypotheses

At time `t`, maintain candidate mechanics/goal programs `p_i` with weights:

```text
log w_i =
    lambda_model * log P_GPT2(p_i | transcript)
  - lambda_length * program_tokens(p_i)
  - lambda_error * replay_error(p_i, history)
```

For deterministic transitions, any material replay contradiction normally sets
the candidate weight to zero. Several programs may remain observationally
equivalent; that ambiguity is preserved rather than collapsed into one story.

GPT-2 periodically receives:

- the shortest surviving programs;
- their exact replay status;
- concise counterexamples for rejected programs;
- the current state and budget.

It then generates repairs or new candidates.

## Counterfactual Fracture with GPT-2 only

For each legal action `a`, execute every surviving candidate program and group
programs by predicted observation. This yields model disagreement without a
second learned model.

A generic controller calculates:

```text
score(a) = expected_task_value(a)
         + beta * reachable_posterior_reduction(a)
         - gamma * irreversible_failure_risk(a)
         - action_cost(a)
```

All semantic quantities—candidate goal predicates, predicted terminal value,
and whether a state is desirable—originate from GPT-2-generated programs. The
controller only performs arithmetic and program execution.

When immediate actions do not distinguish hypotheses, generic search finds a
short sequence that reaches a **fracture state** where the programs predict
different results. This preserves the useful part of Counterfactual Fracture
Search without asking GPT-2 to enumerate a search tree in prose.

## Prior-data-fitted decision learning

Algorithm Distillation is useful but inherits biases from the source learner.
The stronger training target treats GPT-2 as a prior-data-fitted Bayesian
decision model.

1. Sample an ARC-DSL game program from a broad procedural prior.
2. Sample an interaction history under many exploration policies.
3. Compute exact posterior-compatible programs and optimal actions with the
   known generator/interpreter.
4. Train GPT-2 to predict:
   - the hidden mechanics/goal program;
   - the posterior predictive next transition;
   - the Bayes-adaptive action;
   - the experiment that most changes reachable policy;
   - a bounded recurrent memory.

Across enough sampled games, GPT-2 can learn the inference algorithm in its
weights and perform task inference from context. Language pretraining is an
initialization hypothesis, not an assumption: it is always compared with the
same GPT-2 architecture initialized randomly.

## Soft world-state particles

Text context alone may be insufficient. A later variant gives one frozen GPT-2
several small continuous prefix states `z_1 ... z_k`.

Each prefix is a candidate latent world model. After observing a transition:

```text
z_i <- z_i - eta * gradient_z_i(
    -log P_GPT2(observed_delta, status | history, action, z_i)
)
```

Particles receive bootstrap-weighted histories and are reweighted by transition
likelihood. Their predictive disagreement supplies a second, fully GPT-2-based
uncertainty estimate.

Important constraints:

- the base checkpoint remains one model;
- prefix particles are per-game state, not independently pretrained agents;
- updates use only actual environment transitions;
- gains must be measured against intact-context GPT-2 without prefixes.

## Context and memory

GPT-2's native 1,024-token limit is handled through executable state, not by
pretending the limit is absent.

Persistent external state consists of:

- exact frame checkpoints and deltas;
- surviving executable programs;
- program posterior weights;
- failed action prefixes and terminal outcomes;
- GPT-2-generated memory with evidence pointers.

The current prompt contains:

- current exact frame or requested crop;
- recent transitions;
- compact surviving programs;
- the latest memory;
- current budget and legal actions.

Old raw history remains retrievable by exact ID. GPT-2 can call `HISTORY` or
`REPLAY` when a hypothesis requires older evidence.

## Training curriculum

### Gate A — in-context action semantics

Random action-to-direction mappings fixed across multiple levels. This is the
current Phase-0 implementation. It tests whether history changes behavior.

### Gate B — exact program induction

Single-primitive games with known ARC-DSL programs. Hold out palettes, layouts,
action mappings, and parameters. Measure exact program recovery and behavioral
equivalence.

### Gate C — repair from contradiction

Give GPT-2 a near-correct program and one counterexample transition. Require a
minimal repair that passes all replay checks.

### Gate D — composition generalization

Train on primitives and selected pairs; hold out specific compositions such as
`collect -> unlock -> transform`. Success requires synthesizing a novel program,
not remembering a game template.

### Gate E — hidden goals

Mechanics are known or easily inferred, but goal predicates are latent. Train on
full attempts, terminal successes, failures, and cross-level recurrence.

### Gate F — fracture exploration

Candidate programs agree on immediate outcomes but disagree after a reachable
short sequence. Compare GPT-2/program-posterior exploration with random,
myopic-change, and direct-policy GPT-2 under equal action budgets.

### Gate G — public locked ARC games

No trajectory, human replay, environment-derived label, or mutation of a held-
out game may enter its training fold. A result counts only when the same frozen
agent improves on games that were never development-involved.

## Expert iteration without another model

The system can improve itself while preserving the GPT-2-only constraint:

1. GPT-2 proposes programs and plans.
2. The deterministic interpreter verifies and searches them.
3. Successful verified traces become training examples.
4. Contradictions become repair examples.
5. Procedural generation emphasizes grammar regions where GPT-2 fails.
6. Fine-tune the same GPT-2 family checkpoint and repeat.

The interpreter is a source of exact consequences, not a semantic teacher. No
larger model labels the data.

## Model ladder

- **GPT-2 Small (124M):** codec, grammar, hidden-action and primitive gates;
- **GPT-2 Medium (355M):** serious program induction and repair;
- **GPT-2 Large (774M):** composition and hidden-goal experiments;
- **GPT-2 XL (1.5B):** final Kaggle agent if the smaller checkpoints establish
  genuine locked transfer.

All remain original GPT-2 architecture/checkpoints. Scaling is earned by a gate,
not assumed to repair a failed design.

## Final inference loop

```text
RESET game
while budget remains and game not complete:
    expose exact current frame/delta
    GPT2.INSPECT until representation is adequate
    GPT2.INDUCE / REPAIR candidate mechanics and goal programs
    compile and replay-check all candidates
    preserve the posterior, including unresolved alternatives
    use candidates to simulate legal actions and reachable fracture sequences
    GPT2.PLAN and GPT2.ACT using verified rollout evidence
    execute one real action
    append exact transition and terminal signal
    update program posterior and optional soft-prefix particles
    on contradiction, regenerate rather than patching only the favorite theory
    on reset/level transition, retain mechanics and goal evidence but replace
    level-local geometry
```

## What would count as evidence

A lower training loss does not count. Neither does solving a procedural family
seen during development.

The approach earns continuation only if it demonstrates, in order:

1. intact history beats amnesia and corrupted history;
2. generated programs predict held-out transitions exactly more often than
   direct next-frame GPT-2;
3. replay verification improves completion rather than only filtering syntax;
4. program-posterior fracture exploration saves real actions;
5. pretrained GPT-2 beats random initialization under matched compute;
6. a frozen configuration solves at least one additional locked public game or
   materially improves efficiency across several locked games.

Until the final condition is met, ARC-GPT2 is a research program—not an
ARC-AGI-3 solution claim.
